#+title: My NixOS config

** Overview
Multi-host NixOS configuration built with [[https://github.com/hercules-ci/flake-parts][flake-parts]]:
- nixpkgs: stable (=nixos-26.05=) as the base, =unstable= for selected packages, and a separately pinned unstable for CUDA
- [[https://github.com/nix-community/home-manager][home-manager]] for the user environment, run as a NixOS module
- [[https://github.com/Mic92/sops-nix][sops-nix]] for secrets
- [[https://github.com/nix-community/disko][disko]] for declarative disk layouts

Private configuration and all encrypted secrets live in a separate flake, =nix-config-private=.

** Host specification

| Name           | Description                                 | Type    | Arch          |
| homelab        | Workstation (being reinstalled on an HDD)   | Desktop | x86_64-linux  |
| thinkpad-x1-g3 | Thinkpad X1 Extreme Gen 3                   | Laptop  | x86_64-linux  |
| homeserver     | Raspberry Pi 4B                             | Server  | aarch64-linux |
| homerpilab     | Raspberry Pi 4B, 1 TB HDD                   | Server  | aarch64-linux |
| iso            | LiveCD for setup/restore                    | ISO     | x86_64-linux  |

*** homeserver services
- [[https://www.home-assistant.io/][Home Assistant]] - Home automation (ZHA on a ConBee stick, Bluetooth), with the [[https://github.com/Patrick762/hassio-bluetti-bt][Bluetti BLE]] and [[https://github.com/davidrapan/ha-solarman][Solarman]] custom integrations
- [[https://docs.paperless-ngx.com/][Paperless-ngx]] - Document management
- [[https://forgejo.org/][Forgejo]] - Git forge
- [[https://www.samba.org/][Samba]] - File shares for the LAN
- nginx - HTTPS for the services: =*.homeserver.local= on the LAN, plus Let's Encrypt certificates from [[https://tailscale.com/][Tailscale]] for tailnet access
- [[https://restic.net/][restic]] - Encrypted daily backups of Home Assistant and Paperless to homerpilab

*** homerpilab services
- [[https://github.com/restic/rest-server][restic rest-server]] - Append-only backup target for homeserver, with weekly prune and check
- [[https://github.com/nix-community/harmonia][Harmonia]] - Nix binary cache for the other hosts, reachable over Tailscale; thinkpad and homeserver use it as a substituter
- [[https://www.samba.org/][Samba]] - File shares for the LAN

*** thinkpad-x1-g3
- [[https://traefik.io/][Traefik]] - Local HTTPS reverse proxy for development (devenv and Docker), bound to loopback
- [[https://thekelleys.org.uk/dnsmasq/doc.html][dnsmasq]] - Wildcard =*.test= / =*.loc= → 127.0.0.1 for Traefik, reached only through a systemd-resolved DNS delegate
- [[https://github.com/StevenBlack/hosts][StevenBlack hosts]] - Ad/tracker blocklist in =/etc/hosts=
- [[https://ollama.com/][Ollama]] - Local LLMs on the NVIDIA GPU
- Remote builder for the Pis (aarch64 through binfmt/QEMU)
- [[https://github.com/nix-community/disko][Disko]] - Declarative disk layout (btrfs, adoption mode, dual-boot with Windows)
- YubiKey PAM authentication (challenge-response)
- NVIDIA PRIME offload (Intel iGPU primary, NVIDIA dGPU on demand)

*** Networking and security
- *DNS*: all hosts use [[https://www.freedesktop.org/software/systemd/man/latest/systemd-resolved.service.html][systemd-resolved]]. NetworkManager hands it each connection's DHCP/VPN servers, and Tailscale registers MagicDNS as a split-DNS route for the tailnet only, so short names like =homerpilab= work. mDNS (=*.local=, Samba discovery) stays with Avahi; resolved's own mDNS and LLMNR are off. The thinkpad publishes =thinkpad-x1-g3.local= on Wi-Fi, which the Pis use for their remote builder.
- *Firewall*: =tailscale0= is trusted everywhere. On the LAN, homeserver only opens SSH, Samba and 80/443; everything else (Tailscale HTTPS ports) is Tailscale-only. homerpilab opens only SSH and Samba on the LAN; rest-server and Harmonia are Tailscale-only. On the thinkpad, dev ports are open only on Docker bridges, and Docker publishes ports on 127.0.0.1.
- *SSH*: key-only, no keyboard-interactive auth, no root login. The Pis pin the thinkpad's host key. Agent forwarding is off by default.

** Usage

*** Local Rebuilds

Enter the development shell, then use the provided commands:

#+begin_src bash
# Enter development shell
nix develop

# Rebuild NixOS (and home-manager, which runs as a NixOS module)
nix-switch

# Format all Nix files
nix fmt
#+end_src

Private flake inputs are fetched from GitHub with the token in the =nix-access-tokens= sops secret, which =base.nix= includes into nix.conf, so both piotr and root can fetch them.

*** Remote Deployment

homeserver and homerpilab rebuild themselves from a clone in =~/nix-config=, fetching from cache.nixos.org. A first deploy, or a Pi without the token yet, goes from the thinkpad instead. See "Deploying future updates" in [[file:docs/rpi-setup.org][docs/rpi-setup.org]].

** Adding a New Host

1. Create =hosts/{hostname}/default.nix= with the host-specific system configuration. =mkHost= already adds =modules/nixos/base.nix= (nixpkgs, home-manager, the piotr user, nix settings, locale, SSH, resolved, Tailscale) and the private sops modules. Import on top of that:
   - =./hardware-configuration.nix=
   - Profiles: =outputs.nixosModules.server= (always-on), =outputs.nixosModules.desktop= (GNOME workstation), =outputs.nixosModules.rpi4= (Raspberry Pi 4, includes =server=)
   - Features: =outputs.nixosModules.samba=, =outputs.nixosModules.wifi-watchdog=, =outputs.nixosModules.home-cache= (Harmonia substituter on homerpilab)
   - Any relevant =inputs.private-nix-config.nixosModules.*= for secrets
   - Optionally: =inputs.hardware.nixosModules.{profile}=, =inputs.disko.nixosModules.disko=

2. Create =hosts/{hostname}/hardware-configuration.nix= (generate with =nixos-generate-config= or copy from an existing host)

3. Create =home/piotr/{hostname}.nix=. This is the home-manager entry point for the host:
   - Servers import =./global= (git, nix settings, CLI basics)
   - Desktop machines import =./profiles/workstation.nix= (global + emacs, direnv, firefox, fonts)
   - Add further =./features/*= as needed

4. Register the host in =parts/nixos.nix=:
   #+begin_src nix
   new-host = mkHost { hostname = "new-host"; };
   # For aarch64: mkHost { hostname = "new-host"; system = "aarch64-linux"; };
   #+end_src

5. Stage all new files: =git add hosts/new-host/ home/piotr/new-host.nix= (flakes only see git-tracked files)

6. Build and switch on the new host: =nix develop -c nix-switch=

For Raspberry Pi hosts, see [[file:docs/rpi-setup.org][docs/rpi-setup.org]] for the full setup workflow (SD image build, USB SSD boot, sops key provisioning).

** Remote Builds

RPi hosts (aarch64) delegate builds to thinkpad-x1-g3 (x86_64), which runs aarch64 through QEMU binfmt.

- A =builder= user on the thinkpad accepts the Pis' builder key. The key is restricted to =nix-daemon --stdio=, so it gives no shell.
- The key is managed with sops-nix and deployed to =/etc/nix/builder_key=
- The Pis reach the thinkpad as =thinkpad-x1-g3.local= (mDNS) and pin its SSH host key

** Backups

homeserver backs up Home Assistant and Paperless with restic to an append-only =rest-server= on homerpilab, over Tailscale. homeserver can add snapshots but never delete them; retention runs on homerpilab.

Listing, verifying, restoring and rolling back are all scripted (=homeserver-restore= on homeserver). A VM test (=nix build .#checks.x86_64-linux.backup-restore=, also part of =nix flake check=) runs the whole cycle against real Paperless and PostgreSQL: back up, check append-only, verify, wipe, restore and roll back. The step-by-step procedures, including rebuilding homeserver from scratch, are in [[file:docs/backup-restore.org][docs/backup-restore.org]].

** Secrets Management

Secrets are managed via [[https://github.com/Mic92/sops-nix][sops-nix]] with age encryption. Encrypted secrets are stored in the private repository (=nix-config-private=).

*** Key Types by Host

- *homeserver*, *homerpilab*: SSH host key (=/etc/ssh/ssh_host_ed25519_key=)
- *thinkpad-x1-g3*: Standalone age key (=/var/lib/sops-nix/key.txt=)

*** Editing Secrets

#+begin_src bash
cd ~/projects/personal/nix-config-private
sops secrets/homeserver.yaml
#+end_src

*** Public repository hygiene

This repository is public. A commit that bumps =private-nix-config= in =flake.lock= must not describe what changed there. The =commit-msg= hook (enabled by the dev shell) enforces it:
- a lock-only bump must be exactly =chore(flake): bump private-nix-config=
- a commit that also changes public code may mention the bump only as a =Bump private-nix-config= line

** LiveCD ISO

A bootable LiveCD ISO for new host setup (disk partitioning, =nixos-install=) and configuration restore.

#+begin_src bash
nix build .#nixosConfigurations.iso.config.system.build.isoImage
dd if=result/iso/nixos-setup.iso of=/dev/sdX bs=4M status=progress
#+end_src

The ISO boots into a GNOME desktop with Emacs, Claude Code, git, disko, btrfs-progs, sops/age, and standard utilities.

** Directory Layout

#+begin_src
hosts/                     # Per-host NixOS configurations
  {hostname}/
    default.nix            # Host-specific system config
    disk-config.nix        # Disko declarative disk layout (optional)
    hardware-configuration.nix
  homeserver/backup.nix    # restic backups + homeserver-restore (restore.sh)
  homeserver/{bluetti-bt,solarman}.nix  # Home Assistant custom integrations

checks/                    # VM tests, run by `nix flake check` (x86_64)

home/piotr/                # Home-manager configurations
  global/                  # Shared across all hosts (git, nix settings, CLI basics)
  profiles/                # Bundles of features (workstation)
  features/                # Optional modules (emacs, direnv, firefox, mpv)
  {hostname}.nix           # Host-specific user config

modules/nixos/             # Shared NixOS modules, exported as nixosModules.*
  base.nix                 # Added to every host by mkHost
  profiles/                # server, desktop, rpi4
  features/                # user-piotr, samba, wifi-watchdog, home-cache

parts/                     # Flake-parts modules (nixos, modules, checks, iso, overlays, dev-shell, formatter, packages, templates)

overlays/modifications/    # Package overlays (auto-loaded, no registration needed)

pkgs/                      # Custom package definitions

templates/rust-cli/        # `nix flake init -t .#rust-cli` scaffold

docs/                      # Setup guides and runbooks (Pi setup, backup restore, …)
#+end_src
